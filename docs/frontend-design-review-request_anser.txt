알로하(`aloha-yt.xyz`) 프론트엔드 코드베이스 및 화면 구조 패킷에 대한 통합 디스플레이·사용성·디자인 시스템 리뷰 보고서입니다.

1인 운영자가 최소 비용으로 즉시 고도화할 수 있도록 **한국 이용자 정서에 맞춘 모던 에디토리얼·커머스 스타일(깔끔한 백그라운드, 깊이감 있는 세이지 그린/포레스트 톤 포인트, 명확한 타이포그래피 위계)**을 중심으로 실용적인 개선안과 완전한 코드 패치를 제시합니다.

## 1. UI 장점 및 핵심 문제점 요약 (10줄 이내)

- **장점**: Next.js 15 App Router와 정적 SSG+CRON 헬스체크 조합으로 빠르고 신뢰성 있는 로딩을 제공하며, Cloudinary 이미지 자산 매핑 및 복구 파이프라인이 안정적으로 구축되어 있습니다.
- **핵심 문제 1 (CSS 중복·충돌)**: `globals.css` 상단(따뜻한 크림/갈색)과 하단(에디토리얼 백색/세이지 그린)에 동일 선택자 및 CSS 변수가 두 번 정의되어 스타일 간섭 및 불필요한 바이트 낭비가 심합니다.
- **핵심 문제 2 (모바일 내비게이션 및 헤더 점유)**: 모바일에서 Sticky 헤더 + 관리자 툴바가 상단 150px 이상을 가리며, 검색 폼과 네비게이션이 복잡하게 줄바꿈되어 본문 시야를 크게 해칩니다.
- **핵심 문제 3 (본문 Typography 결함)**: `.rich-text`에 일률 적용된 `white-space: pre-line`으로 인해 WordPress에서 이관된 HTML의 불필요한 줄바꿈이 거대한 여백으로 노출되고, 표(Table)·인용구·이미지 캡션 디자인이 다듬어지지 않았습니다.

## 4. 화면별 상세 리뷰 및 개선 가이드

### 4.1 전역 헤더 · 검색 · 푸터
- **문제점**: 데스크톱 헤더는 높이가 과도하게 높고(76px+), 검색 폼이 메인 메뉴 우측에 비대하게 배치되어 있습니다. 모바일에서는 로고, 메뉴, 검색 폼이 3단 축적되어 Header 높이만 140px을 넘습니다.
- **개선안**:
  1. 헤더 높이를 데스크톱 `60px`, 모바일 `52px`로 컴팩트화합니다.
  2. 검색 폼은 모바일에서 기본적으로 아이콘 버튼으로 제공하고 클릭 시 슬라이드다운 패널로 열리게 변경하거나, 네비게이션 아래 한 줄로 슬림하게 바꿉니다.
  3. 푸터의 사업자 정보는 `font-size: 0.82rem`, `line-height: 1.6`으로 정돈하고, 카카오톡 고객센터 CTA 버튼을 가시성 있게 강조합니다.

### 4.2 홈 / 글 목록 (`/`, `/page/2`)
- **문제점**: 최신 글 카드가 1열 가로 분할 카드(`grid-template-columns: 220px 1fr`)로 나열되는데, 모바일에서 이미지가 거대하게 떨어지거나 제목 간격이 느슨합니다.
- **개선안**:
  1. 홈 상단 배너를 슬림화하고, 카테고리 태그 + 작성일 + 댓글 수를 한 줄 칩(Chip) 형태로 상단에 정리합니다.
  2. 제목 폰트 크기를 모바일 `1.25rem`, 데스크톱 `1.5rem`으로 조정하고 `line-height: 1.35`를 부여하여 한국어 제목 줄바꿈 미감을 잡습니다.

### 4.3 일반 글 · 고정 페이지 (`/res`, `/terms`, `/227` 등)
- **문제점**: WP HTML의 `white-space: pre-line` 설정으로 인해 HTML태그 사이의 `\n`이 전부 빈 줄로 출력됩니다. 표(`table`)에 경계선과 Padding이 없고 반응형 오버플로우 처리가 없어 모바일 화면을 뚫고 나갑니다.
- **개선안**:
  1. `.rich-text` 내부에서는 `white-space: normal`을 기본으로 지정하고, 순수 텍스트 문단(`.rich-text p`)에만 가독성 있는 `line-height: 1.8`, `margin-bottom: 1.25em`을 줍니다.
  2. 표 요소(`table`)를 CSS `display: block; overflow-x: auto;` 및 Nth-child 줄무늬(Zebra pattern)로 자동 스타일링합니다.

### 4.4 상점 / 상품 상세 (`/shop`, `/product/210`)
- **문제점**: `/shop` 목록 카드(`ShopCatalog`)가 1열 좌우 배치 카드 형태로 나열되어 스크롤 피로도가 높고, 카드 내 품절/예약 상태 태그가 이미지 위와 본문 아래에 중복 출력됩니다.
- **개선안**:
  1. `/shop` 카탈로그를 **2x2 (모바일) / 3x3 ~ 4x4 (데스크톱)** 그리드 카드로 전환하여 한눈에 많은 매물이 비교되도록 바꿉니다.
  2. 매물 특성에 맞춰 **[특수보장] [즉시양도] [SALE] [SOLD OUT]** 전용 뱃지를 이미지 좌상단에 겹쳐 정돈하고, 가격(정가 취소선 + 할인가)을 강조합니다.

### 4.5 장바구니 · 결제 · 주문 완료 (`/cart`, `/checkout`)
- **문제점**: 결제 페이지에서 계좌번호 정보(`bank-card`)가 너무 밝은 녹색 배경으로 튀어 보이고, 주문자 정보 폼 필드 입력창의 포커스 상태가 시각적으로 불분명합니다.
- **개선안**:
  1. 무통장 입금 계좌 박스에 **1클릭 복사 기능(계좌번호 복사)** 버튼을 추가하여 실제 입금 편의성을 높입니다.
  2. 폼 입력 요소 포커스 시 `border-color: var(--accent)`와 `box-shadow: 0 0 0 3px var(--accent-light)`를 적용하여 또렷한 피드백을 제공합니다.

### 4.6 관리자 툴바 & 편집기 (`/loginpage/*`)
- **문제점**: 공개 화면 상단에 플로팅되는 관리자 툴바(`AdminPublicToolbar`)가 Sticky 헤더와 충돌합니다. 에디터(`AdminHtmlEditor`) 하단 저장 버튼이 스크롤 아래 멀리 숨어 있어 긴 글 작성 시 저장 피로도가 높습니다.
- **개선안**:
  1. 툴바 활성화 시 `body` 상단 패딩을 자동으로 부여하거나, 툴바를 화면 우측 하단 컴팩트 FAB(Floating Action Button) 또는 슬림 바 형태 형태로 조정합니다.
  2. 글/상품 편집기 하단에 **Sticky Action Bar**(저장/초안/미리보기)를 적용하여 스크롤 위치와 상관없이 1클릭 저장이 가능하도록 개선합니다.

## 6. WCAG 접근성 (Accessibility) 점검 리포트

1. **색상 대비 (Color Contrast)**:
   - 보조 텍스트 색상 `--muted: #68726b`가 밝은 오프화이트 배경 상에서 대비율 `3.8:1`로 WCAG AA 기준(`4.5:1`)에 미달합니다. $\rightarrow$ **`#525b55`**로 진하게 조정하여 대비율 **`5.2:1`** 확보.
2. **키보드 포커스 (Focus Visible)**:
   - 버튼 및 네비게이션 링크에 Custom Focus Ring이 없어 키보드 탭 이동 시 위치 파악이 어렵습니다. $\rightarrow$ 전역 `*:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }` 추가.
3. **터치 타깃 크기 (Touch Target)**:
   - 수량 조절 버튼(`.quantity-button`: 34x34px) 및 모바일 네비 링크의 클릭 영역이 작습니다. $\rightarrow$ `min-height: 44px`, `min-width: 44px`로 확장.
4. **오류 메시지 & ARIA**:
   - 비밀번호 보호 글 및 주문 폼 에러 문구(`.warning-text`)가 단순 색상으로만 구분됩니다. $\rightarrow$ `role="alert"` 속성 부여 및 에러 아이콘 추가.

## 7. 성능 & 로딩 최적화 (CLS / LCP / 폰트 / 이미지)

1. **외부 WebFont 호스팅 최적화**:
   - 현재 `cdn.jsdelivr.net`에서 `NanumSquareRound.woff`와 `GmarketSansMedium.woff`를 외부 요청 중입니다.
   - **개선**: WOFF2 포맷으로 로컬 `public/fonts/`에 저장 후 `font-display: swap`을 적용하고 `layout.tsx`에서 `<link rel="preload">`를 걸면 FOUT/FOIT가 사라지고 **LCP가 약 250ms 단축**됩니다.
2. **Layout Shift (CLS) 방지**:
   - 상품 카드 이미지 및 블로그 피드 이미지에 `aspect-ratio: 16 / 9` 또는 `4 / 3`을 CSS에 명시하여 이미지 로딩 전 영역 확보.
3. **`backdrop-filter: blur()` 남발 제거**:
   - 모바일 스크롤 시 저가형 모바일 브라우저에서 GPU 프레임 드롭을 유발하는 카드 단위 `backdrop-filter: blur(12px)`를 제거하고, 솔리드 백그라운드 `background: var(--paper)`로 교체합니다.

## 8. CSS 코드 스멜 지적 및 리팩토링 단위

1. **`app/globals.css` 중복 `:root` 선언 충돌**:
   - 파일 1줄~10줄의 레거시 브라운 토큰과 파일 450줄 이하의 에디토리얼 그린 토큰이 충돌 중입니다. 상단 레거시 구역 전체를 삭제/통합해야 합니다.
2. **`white-space: pre-line` 오남용**:
   - `.rich-text p, .rich-text li` 전체에 걸린 `white-space: pre-line` 스타일이 WP HTML 내 태그 사이의 줄바꿈 문자를 전부 빈 텍스트 노드로 바꿔 여백을 깨뜨리고 있습니다. 이를 즉시 제거해야 합니다.
3. **컴포넌트 분리 추천**:
   - `globals.css` 내의 `.admin-*` 스타일(전체 800줄 이상)을 `app/loginpage/admin.css` 또는 CSS Module로 분리하면 공개 방문자가 다운로드하는 초기 CSS 용량이 35KB에서 **12KB**로 단축됩니다.

## 10. 핵심 질문 9가지 명쾌한 답변

1. **920px 본문 폭과 1280px site-frame의 적절성**:
   - **판단**: 글 읽기 본문은 `820px`가 최적입니다 (920px은 한 줄당 글자 수가 90자를 넘어 눈이 피로함). 상점/카탈로그 및 관리자 테이블은 `1160px` 컨테이너가 가장 균형 감각이 좋습니다.
2. **데스크톱/모바일 헤더 및 검색 단순화**:
   - 데스크톱에서는 검색창을 우측에 슬림하게 고정하고, 모바일에서는 검색 버튼 클릭 시 네비게이션 하단에 토글되는 레이어로 단순화하여 헤더 높이를 `140px` $\rightarrow$ `52px`로 압축합니다.
3. **24px radius와 반투명 패널 반복 문제**:
   - **개선**: 패널의 불필요한 `backdrop-filter`와 큰 Radius(24px)를 제거하고, 일반 카드는 `10px`, 버튼/입력창은 `6px`의 절제된 Radius와 순백색(`--paper: #ffffff`) 카드로 위계를 살립니다.
4. **WordPress HTML 안전 유지 및 글 품질 향상**:
   - `white-space: pre-line` 버그를 제거하고, 문단 간격 `margin-bottom: 1.25em` 지정 및 표(`table`)에 CSS 자동 가로 스크롤과 줄무늬 서식을 입혀 원본 HTML을 손대지 않고 시각적 품질만 높입니다.
5. **상품 목록 비교 효율화 카드 구조**:
   - 기존 1열 리스트형에서 **2x2 / 3x3 그리드 카드**로 변경하고, 대표 이미지 위에 [SALE], [RESERVED], [SOLD OUT] 뱃지를 선명하게 포개어 직관적인 매물 비교 환경을 제공합니다.
6. **관리자 툴바의 모바일 화면 점유 문제**:
   - 모바일 환경에서는 툴바의 긴 텍스트 경로를 숨기고 슬림한 우측 하단 플로팅 아이콘(FAB)으로 전환하여 화면 가림 현상을 완전 방지합니다.
7. **관리자 편집기 저장/업로드 피드백 정리**:
   - 스크롤과 무관하게 하단에 고정되는 **Sticky Action Bar** 및 상단 "Cloudinary 임시 업로드 완료" 상태 안내 토스트 바를 통해 1인 운영자의 저장 안심감을 확보합니다.
8. **`app/globals.css` 정리 전략**:
   - CSS Module로 전면 교체하지 않고, 충돌되는 레거시 브라운 토큰 구역을 삭제/통합하고, 관리자 전용 CSS 구역을 분리하는 것만으로 즉시 깨끗한 구조를 갖출 수 있습니다.
9. **외부 폰트 유지 vs 로컬 호스팅/시스템 폰트 전환**:
   - **권장**: 외부 CDN WOFF 폰트 호출을 제거하고, 본문 폰트는 시스템 지원 폰트(Pretendard/Apple SD Gothic Neo)로 전환하고 Heading용 GmarketSans만 로컬 WOFF2로 preload 호스팅하는 것이 성능과 분위기를 동시에 잡는 최선의 선택입니다.
